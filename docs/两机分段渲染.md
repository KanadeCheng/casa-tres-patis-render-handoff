# 两机分段渲染与统一编码

2026-11-02用户更新：另一台电脑处理**1～3000帧**，当前电脑处理**3001～4800帧**。保持同一工程、同一画质、24fps；分段结束只交付原始编号RGB16位PNG，双方完成后再统一编码。长渲染监控间隔为**1小时**，正常时保持安静。任务仍仅限渲染及技术核验。

## 启动各自分段

另一台电脑先按交接文档完成环境检查，然后在仓库根目录运行：

```text
python scripts/start_render.py --mode part --start-frame 1 --end-frame 3000 --output "<前段输出文件夹>"
```

当前电脑已使用：

```text
python scripts/start_render.py --mode part --start-frame 3001 --end-frame 4800 --output "<后段输出文件夹>"
```

`part`模式复用与10秒样片相同的Cycles设置，自动检查源文件和设备，逐帧输出并做CRC/SHA-256核验；不改变工程帧范围，不重编号，不重置水纹或季节时间，不单独编码视频。首次即从该段真实起点选择正确相机，保留所有既定动作与合成。中断后使用原命令和同一输出目录继续，只补缺帧或损坏帧。

此分工下**不要运行默认`--mode render`**，它是旧单机完整4800帧模式；也不要在另一段尚未到齐时执行`--mode encode`。若另一台电脑已经开始前段渲染，不要仅为更新本文件而中断健康的渲染进程；只需保持既定前段范围和同样画质。

每段完成状态为`part_complete`，含`part_manifest.json`、`part_validation.json`、`render_manifest.json`和`frames_index.json`。每台电脑在本段完成后停止自身监控，保留序列等待汇合，不报告整片已经输出。

## 汇合时需传递的文件

将前段输出文件夹从另一台电脑复制到最终合并电脑，保留：

- `frames/00001.png`～`03000.png`，后段为`03001.png`～`04800.png`；
- 各自`render_manifest.json`、`frames_index.json`、`part_manifest.json`和`part_validation.json`。

源工程SHA-256必须相同；画幅、帧率、色彩、采样、位深和Blender版本必须兼容。允许不同GPU后端，不能混入旧8fps低清序列。不要把两段独立压缩视频再拼接，也不要只复制图片而丢掉校验清单。两台机器不必具有相同磁盘路径。

## 两段到齐后的统一编码

```text
python scripts/merge_parts.py --first "<前段输出文件夹>" --second "<后段输出文件夹>" --output "<统一序列文件夹>"
python scripts/start_render.py --mode encode --output "<统一序列文件夹>"
```

合并工具先核验全部4800帧与各自索引再写统一目录，不覆盖冲突文件；优先硬链接以节省同盘空间，跨盘时复制，保留原段。工具本身不渲染、不重新调色。编码阶段直接使用原16位PNG，输出200秒、24fps、1080p无字幕MP4，保持Standard/曝光0避免重复AgX变换，再做真实时长、帧数和解码核验。

只有两段文件确实到齐、统一校验成功且完整视频编码核验完成后，才交付“整片完成”。缺少另一台电脑的序列时明确等待，不假定能自动从远程电脑取得文件。
